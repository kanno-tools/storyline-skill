# 工程4｜別の目で読ませる（必須）

作った本人は、自分が知っている前提で読んでしまうので、話の飛び・繰り返し・言い過ぎ・数字の食い違いに気づけない。作り方を知らない相手に読ませて拾う。自分で読み直すことの代わりにはならない。

## 使い方

1. 素材と、ストーリーライン表（タイトル・見せ方・根拠の数字と出所の列を含む）を用意する。タイトルだけで話が通るかと、根拠の数字が正しいかを、両方見てもらうため
2. 下の指示文を、作り方・使ったスキル・こだわった点を伝えずに、別のエージェント（Claude Code なら Agent ツール、Gemini CLI なら新しいセッション）に渡す。`{MATERIAL}`・`{TABLE}`・`{DECISION}` を置き換える
3. 返ってきた指摘を採否表にする。全部は直さない。1件ずつ「採用／不採用／保留」を決め、迷うもの（意味が変わる言い換え、並びの組み替え）は依頼者に採否を委ねる
4. 採用分を直し、SKILL.md の点検をもう一度通す。不採用は理由を1行残す
5. ここまでを1回（1ラリー）と数え、1回で止める。採否表を成果物の別添にし、「指摘件数・採用件数・残っている懸念」を3行で添えて、もう1回回すかは依頼者に聞く

### 採否表

| # | 行 | 指摘（原文のまま） | 種別 | 採否 | 対応／理由 |
|---|---|---|---|---|---|
| 1 | 3 | 前の行から話が飛んでいる | 論理 | 採用 | 間に1行足した |
| 2 | 5 | 「大幅に」は根拠が見えない | 言い過ぎ | 採用 | 数字に置き換えた |
| 3 | 2 | 「時差枠」が分かりにくい | 日本語 | 不採用 | 1行目で定義済み |

種別は「論理」「日本語」「言い過ぎ」「数字」「抜け」の5つ。素材に数字が無くて直せない指摘は「保留」にし、理由に「素材不足：〜の数字が要る」と書く。

### 構成案
{TABLE}

### 見ること（行番号つきで報告）
1. **話の通り**：タイトルだけを上から読んで、話が飛ぶ・戻る・同じことを2度言う・前提なしに結論が出る箇所
2. **目的への答え**：最後まで読んで、読み手が目的を果たせるか。判断に要るのに抜けている問い（費用・期間・リスク・やめる条件など）
3. **言い過ぎ**：根拠が見えない評価語（「大幅に」「十分」「限定的」「問題ない」「にとどまる」）や、素材より強い言い切り
4. **1行の自立**：その行だけを読んで意味が通らないもの。「この」「その」で他の行を指しているもの、主語や対象が抜けた圧縮語
5. **日本語**：引っかかる言い回し、表記ゆれ、定義のない略語・造語
6. **数字**：素材に無い数字、計算の誤り、同じ量が行によって違う値、比べる2つの数字の母集団・期間・統計量（平均か中央値か）の食い違い、出所の欠落
7. **数と中身の一致**：タイトルで予告した数（「3案」など）と中身の数の食い違い、冒頭のまとめと後ろのページのずれ

### 出力
- 上の1〜7ごとに、行番号・該当箇所の引用・何が問題か・直し方の案。該当が無ければ「該当なし」
- 直すべき順に並べた上位5件
- 欠点を最低3つ挙げること。無傷の資料はない
