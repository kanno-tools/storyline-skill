# 工程4｜別の目で読ませる

作った本人は、自分が知っている前提で読んでしまうので、話の飛び・繰り返し・言い過ぎに気づけない。作り方を知らない相手にタイトル列を読ませて拾う。

## 使い方

1. ストーリーライン表を**タイトル列だけ**にする（役割・質問・根拠の列は渡さない。タイトルだけで話が通るかを見るため）
2. 下の指示文を、作り方・使ったスキル・こだわった点を伝えずに、別のエージェント（Claude Code なら Agent ツール、Gemini CLI なら新しいセッション）に渡す。`{TITLES}` と `{DECISION}` を置き換える
3. 返ってきた指摘を採否表にする。全部は直さない。1件ずつ「採用／不採用／保留」を決め、迷うもの（意味が変わる言い換え、並びの組み替え）は依頼者に見せる
4. 採用分を直し、SKILL.md の点検をもう一度通す

### 採否表

| # | 行 | 指摘（原文のまま） | 種別 | 採否 | 対応／理由 |
|---|---|---|---|---|---|
| 1 | 3 | 前の行から話が飛んでいる | 論理 | 採用 | 間に1行足した |
| 2 | 5 | 「大幅に」は根拠が見えない | 言い過ぎ | 採用 | 数字に置き換えた |
| 3 | 2 | 「時差枠」が分かりにくい | 日本語 | 不採用 | 1行目で定義済み |

種別は「論理」「日本語」「言い過ぎ」「抜け」の4つ。素材に数字が無くて直せない指摘は「保留」にし、理由に「素材不足：〜の数字が要る」と書く。

## 指示文（ここからコピー）

あなたは会議資料のレビュアーです。これから渡すのは、ある資料の各ページのタイトルを上から順に並べたものです。この資料の目的は「{DECISION}」を読み手に決めてもらうことです。どう作られたかは知らされません。推測で補わず、書かれている文だけで判断してください。

### タイトル列
{TITLES}

### 見ること（行番号つきで報告）
1. **話の通り**：上から読んで、話が飛ぶ・戻る・同じことを2度言う・前提なしに結論が出る箇所
2. **決めてもらうことへの答え**：最後まで読んで、読み手が「{DECISION}」を判断できるか。判断に要るのに抜けている問い（費用・期間・リスク・やめる条件など）
3. **言い過ぎ**：根拠が見えない評価語（「大幅に」「十分」「限定的」「問題ない」）や、事実より強い言い切り
4. **1行の自立**：その行だけを読んで意味が通らないもの。「この」「その」で他の行を指しているもの、主語や対象が抜けた圧縮語
5. **日本語**：引っかかる言い回し、表記ゆれ、定義のない略語・造語

### 出力
- 上の1〜5ごとに、行番号・該当箇所の引用・何が問題か・直し方の案。該当が無ければ「該当なし」
- 直すべき順に並べた上位5件
- 欠点を最低3つ挙げること。無傷の資料はない
